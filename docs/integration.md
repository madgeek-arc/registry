# Registry — Integrations

| Direction | Counterpart | Protocol | Purpose | Configuration key | Evidence path/symbol |
|---|---|---|---|---|---|
| provided | Host Spring Boot application (in-process) | Java service API (`ResourceService`, `ResourceTypeService`, `SearchService`, `VersionService`, `GenericResourceService`, ...) | Store, validate, version and search resources | `registry.*` | `registry-starter-service/.../autoconfigure/RegistryServiceAutoConfiguration.java` |
| provided | HTTP clients, `registry-starter-client` | REST JSON/XML | Same over HTTP. Dump/restore, ResourceSync, typed records | host's `server.*`, `registry.rest.enabled` | `registry-core-rest/.../controllers/*` |
| provided | JMS subscribers | JMS topics `{prefix}.{resourceType}.{create,update,delete}`, JSON text messages, type id property `_type` | Resource change notifications | `registry.jms.prefix` (default `registry`) | `registry-starter-jms/.../jms/JmsResourceListener.java` |
| consumed | PostgreSQL with pgvector and tablefunc | JDBC/JPA (HikariCP), Flyway | Primary storage, full-text and vector search | `registry.datasource.*`, `registry.jpa.*`, `spring.flyway.*` | `configuration/HibernateConfiguration.java`, `db/migration` |
| consumed | Elasticsearch 9.x | HTTP (Elasticsearch Java client, `Rest5Client`), basic auth when username and password are set | Indexing, keyword/semantic/hybrid search, recommendations, startup reconciliation | `registry.elasticsearch.uris` (every entry is a node), `.username`, `.password`, `.enabled` | `registry-starter-elasticsearch/.../autoconfigure/ElasticAutoConfiguration.java#restClient` |
| consumed | ActiveMQ (Classic) broker | OpenWire through `ActiveMQConnectionFactory` | Publish change events | `registry.jms.host` (default `tcp://localhost:61616`), `.username`, `.password`, `.enabled` | `JmsAutoConfiguration.ConfigureJms#activeMQConnectionFactory` |
| consumed (client starter) | Remote registry | HTTP REST through one shared `RestTemplate` with connect and read timeouts | Client-side service implementations | `registry.base`, `registry.client.connect-timeout`, `registry.client.read-timeout` | `registry-starter-client/.../autoconfigure/RegistryClientAutoConfiguration.java` |
| consumed | Embedding model (Spring AI transformers, ONNX) | `all-MiniLM-L6-v2` model and tokenizer packaged in the service starter jar, copied to a temporary cache at startup | Compute 384-dim embeddings | `spring.ai.embedding.transformer.*` (defaults set by `RegistryEmbeddingModelDefaults`) | `registry-starter-service/src/main/resources/onnx/` |

## Provided interfaces

- REST: [api.md](api.md). The OpenAPI document is generated by springdoc at runtime.
- JMS payloads: `registry-core-api/.../domain/jms/ResourceJmsCreated`, `ResourceJmsUpdated` (new and
  previous payload), `ResourceJmsDeleted`. Each carries `resourceId`, `resourceType`, `resource`
  (the payload) and `payloadFormat`. Messages are serialised by Jackson 3's
  `JacksonJsonMessageConverter` as text messages.
- Resource-type additions and deletions are **not** published to JMS (they're logged as `WARN`).
 (`JmsResourceListener#resourceTypeAdded/#resourceTypeDelete`)
- A resource type change is published as `delete` on the old type, carrying the previous resource,
  plus `create` on the new type, carrying the new resource. (`JmsResourceListenerTest`)

## Failure behaviour

| Situation | Behaviour | Evidence |
|---|---|---|
| Version, chunk-embedding, Elasticsearch or JMS listener throws after a DB change | Logged at `ERROR` (`Error notifying listener`). The DB change stands, so version history, embeddings, the index and subscribers drift | `monitor/ResourceMonitor` |
| Elasticsearch out of sync | Reconciled at the next startup: DB→index re-adds. Index-only entries are only logged | `SearchIndexConsistencyService` |
| Missing Elasticsearch index during reconciliation | Recreated from the resource type definition | `SearchIndexConsistencyService#ensureIndexExists` |
| JMS broker unavailable | `JmsTemplate.convertAndSend` fails per event and is logged. Events aren't persisted or retried, so they're lost | `JmsResourceListener`, `ResourceMonitor` |
| Restore of a broken item | Skipped (`AlwaysSkipItemSkipPolicy`) | `BackupRestoreConfig#resourcesStep` |
| Dump read errors | Retried indefinitely (`AlwaysRetryPolicy`) and skipped on write errors | `BackupRestoreConfig#resourcesDumpStep` |
| Remote registry slow or unreachable (client starter) | `ResourceAccessException` after `registry.client.connect-timeout` (10 s) or `registry.client.read-timeout` (60 s) | `RegistryClientAutoConfiguration`, `RegistryClientAutoConfigurationTest` |
| Elasticsearch node unreachable | `Rest5Client` round-robins over the configured `uris` and retries a failed request on the next node. No timeouts are set, so the client library defaults apply | `ElasticAutoConfiguration#restClient` |
